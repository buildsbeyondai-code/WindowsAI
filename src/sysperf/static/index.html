    How SysPerf works, end to end, in three layers. Sense & serve: a warm PowerShell session runs the read-only probe every sampling interval, the collector scores it and the waitress-served Flask API (127.0.0.1 only) hands the snapshot to this page. Learn & remember: samples go to SQLite (raw for days, hourly for a year), the adaptive scorer and trend/root-cause engines learn from them, and the health monitor raises notifications. Act & evolve: the Auto-Improve loop applies only policy-approved reversible fixes, the code-evolution engine proposes AI patches that are sandboxed, benchmarked and audited, and the supervisor restarts the service or rolls a bad patch back.     Recent auto-quits —
    How it decides
    Every 15 s the dashboard checks each listed app. An app is quit only when none of its processes has a visible window — a minimized window still counts as open — for the chosen time, and never within a minute of it starting. You decide per app: until you choose Allow, SysPerf only asks (with a notification); Never keeps it running for good. An app that is busy — a call, a download, a sync — is left alone that round. Every quit can be undone with Reopen, which starts the exact program that was closed. Only apps on your list are touched; Windows, security software, browsers, WSL and this dashboard can never be added.

    What this does
    Runs wsl --shutdown after a short delay, freeing the entire vmmemWSL footprint back to Windows. It also stops this dashboard, which runs inside WSL; it returns on the next WSL start — open a terminal, or its service starts at boot. Any unsaved work inside WSL is lost.

    OneDrive syncs while locked, pauses while you work

    Last completed sync: —
    Lock-state policy, and what "disable control" means
    OneDrive syncs while the machine is locked (catching up while you are away) and stops while unlocked (keeping CPU and disk free while you work). A manual Start or Stop is respected until the next lock-state change.
    Disable OneDrive control makes this dashboard completely hands-off: no stop at start-up, no lock-state autostart or auto-stop, and manual Start/Stop turned off. OneDrive then behaves exactly as if this dashboard were not installed. The choice survives a restart.

    Explorer CPU watchdog restarts the shell when it pins CPU

    Recent Explorer CPU: —
    Why Explorer spikes, and what the watchdog does
    Windows Explorer periodically spikes CPU when a shell extension, thumbnail build or cloud-sync overlay handler gets stuck. When enabled, the watchdog restarts the shell once explorer.exe stays at or above 25% CPU across 2 consecutive samples, then waits out a cooldown so it cannot thrash. Restarting Explorer is reversible and loses no data: Windows relaunches the taskbar and desktop immediately and open applications are unaffected.
