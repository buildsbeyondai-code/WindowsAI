# SysPerf audit, 31 October 2026 (release 5.4.5)

Scope: every category, measured on the live install (5.4.4, Windows 11, WSL 2).
Sources: the runtime log (all WARNING/ERROR lines since 28 Oct), the
self-evolution audit trail, `/api/diagnostics`, latency of 14 endpoints, a
browser sweep of all 8 tabs and 17 Details sections (console errors, failed
requests, cut-off text, literal `null`), screenshots in both themes, ruff with
17 extra rule families (bandit, blind-except, perf, datetime, …),
PSScriptAnalyzer, response headers, the notification inbox, disk use of the
data folder, and the AppX deployment log.

The request was the top 50. The audit found **41 genuine issues**; the rest of
what the tools reported was checked and is not a defect (listed at the end).
Padding the list to 50 would have meant reporting style preferences as bugs.

## Checked and not defects

- `shell="pwsh"` (17 hits): a field of the fix registry naming the shell, not
  `subprocess(shell=True)`.
- f-string SQL (9): only column names from code are interpolated; values are
  bound parameters.
- `0.0.0.0` (1): the Host guard compares against it; nothing binds to it.
- `/tmp` (5): bubblewrap arguments for the sandbox's private tmpfs.
- Naive local datetimes in trends: the rollups are deliberately local days.
- Latency: every endpoint answers in under 0.3 s; footprint 41 MB, 0.24 % CPU.
- Browser: no console errors and no failed requests on any tab.
- "Live CPU by process: no snapshot yet": only in the first minute after a restart.
