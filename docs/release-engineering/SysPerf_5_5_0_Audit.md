# SysPerf 5.5.0 release-path audit

**Decision: hold the 5.5.0 packaged release.** The release workflow caught a real defect in the one-shot measurement path. The tagged source improves on 5.4.0 in several respects, but its release workflow did not publish the tagged Windows build. Two more defects affect whether users can trust update verification and rollback.

**Scope.** [buildsbeyondai-code/WindowsAI at commit 83d718f](https://github.com/buildsbeyondai-code/WindowsAI/tree/83d718f114679efc107acf9d35896777fdfc3f49). The v5.5.0 tag and main resolved to the same commit during inspection. The GitHub latest-release API returned [v5.4.9](https://github.com/buildsbeyondai-code/WindowsAI/releases/tag/v5.4.9). This does not establish what version Microsoft serves through the Store. No production changes were made. The assessment covers the product lifecycle through code inspection, Linux execution, fault injection and historical GitHub-hosted Windows executions. Native installed-app, independent hardware, human accessibility and 24-hour field verification remain open. This is not an external penetration test or an exhaustive review of every statement in every file.

## Findings and required acceptance evidence

1. **Release blocker — fresh data is never requested on the smoke path.** The packaged smoke wrapper delegates to --once. The CLI prints latest from an existing snapshot and exits successfully even when it is empty. A warm profile could mask the defect by providing old data. Require a bounded, fresh collection, machine-readable failure and an appropriate exit code. Require clean and prepopulated profiles to pass the native gate with a timestamp from the current call. The current PR path filter also omits CLI-only changes. [Entry point](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/packaging/msix/sysperf_app.py#L9) · [CLI](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/src/sysperf/cli.py#L169)
2. **Security blocker — signature acceptance depends on human-readable text.** The success sentinel is the English word “signed”; the failure text can contain certificate subject text. Injected output “NotTrusted CN=Unrelated signed Company” with process status 0 passed the Python check. The PowerShell publisher test also uses an unanchored match. Use explicit success/failure and approved signer identity; test authenticated whole-package integrity, particularly for Python NuGet and PowerShell ZIP content. Checking a launcher alone does not cover its DLLs. Parser acceptance is reproduced; successful exploitation on Windows is unverified. [Verification](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/src/sysperf/upgrader.py#L154) · [Staged Python](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/src/sysperf/upgrader.py#L569)
3. **Recovery blocker for automatic deployment — code can change before recovery state is durable.** Apply merges before writing the pending marker. With a marker-write failure, a fresh rollback request had no recorded application to reverse. Separately, if reverting installed Python dependencies fails, git_rollback logs a warning and returns; a caller can still report rollback success. Put durable intent ahead of mutation, recover after restart, and confirm both the commit and actual dependencies. [Apply and rollback](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/src/sysperf/codevolve.py#L1524) · [Dependency rollback](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/src/sysperf/codevolve.py#L215)
4. **Recommendation accuracy — one result can be credited to multiple fixes.** In a controlled test, CPU decreased from 50% to 40% after two fixes. Each got a 20% benefit entry, though only the group was observed. Pending IDs are drawn from the planned set and the assignment is not filtered by individual execution outcome. The recommendation also calls a recency-weighted estimate an average over all runs. Preserve observed history and uncertainty, record execution outcomes, and demonstrate the corrected UI on legacy, grouped, failed and isolated actions. [Verification loop](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/src/sysperf/autoimprove.py#L233) · [Presentation](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/src/sysperf/explain.py#L35)
5. **Endurance evidence — missing telemetry can pass.** The verdict treats missing age as zero, checks for an explicit false health value and can skip its memory-growth check without enough valid measurements. Make completeness and covered time acceptance conditions before using a soak to support readiness. [Soak harness](https://github.com/buildsbeyondai-code/WindowsAI/blob/v5.5.0/tools/soak.py#L35)
6. **Distribution and field coverage remain open.** Run installed Windows activation, WebView2 rendering, Store-mode consent, action/undo, update while running, history preservation, second account, sleep/resume, and uninstall on supported systems. The manifest admits build 19041, which extends below Windows 11. Determine and test the actual minimum or adjust the manifest and documentation. Keep build-directory execution, sideloading and Store delivery distinct in the results. ## How to use the findings

Start with the packaging failure, verification boundary and recovery transaction. Preserve the package assertions that caught the failure. Use disposable Windows hosts for native tests and retain logs and installer hashes. Treat the previous 8.7/10 as a historical repository rating, not evidence that these gates passed. There is no measured whole-PC speedup or defensible whole-product 10/10 from this review.
