## Packaging test (25 October 2026)

Run with the owner's consent, from an elevated prompt for two steps only.

1. The scripted SysPerf was stopped and its data folder snapshotted (34 files).
2. A one-day, leaf (not CA) code-signing certificate `CN=SysPerf` was created
   in the user's store. Copies of the 4.1.0 and 5.0.0 packages were signed by
   thumbprint, so no private-key file was written. The certificate was trusted
   in Local Machine → Trusted People only.
3. 4.1.0 installed and launched: `SysPerf.exe` from WindowsApps served its own
   dashboard. A foreign Host was answered (200): the hole 5.0 closes.
4. Upgrade to 5.0.0 in place: one package, version 5.0.0.0, and the hourly
   history from before the upgrade still present. Foreign Host → 403,
   cross-origin POST → 403, CSP present, window "SysPerf" open.
5. Uninstall: no package, no install folder, no package data folder, no
   process left.
6. Cleanup: certificate removed from Trusted People and deleted with its
   private key; signed copies deleted. A sweep found no `CN=SysPerf`
   certificate in any store. The unsigned Store upload is unchanged
   (SHA-256 C377EB63…37A33). The scripted SysPerf was restarted and was
   healthy.

**Finding.** With a scripted install present, the packaged app is *not*
isolated. Windows virtualizes files a package creates under `AppData`, but
`%LOCALAPPDATA%\SysPerf\data` already existed, so the packaged app read and
wrote the scripted install's state (settings, history, logs). Nothing harmful
ran: its cycles executed no fix. However, uninstalling the Store app leaves
that folder, so PRIVACY.md now says so. On a clean machine the folder is
created by the package and removed on uninstall. That case is still to be
observed.

## Risks and remaining work

  packaging test on a clean machine (no scripted install).
- **Unverified claims:**
  - MSIX on a clean machine (the developer-PC test passed).
  - A 24-hour `tools/soak.py` run.
  - The real side effect of four controls (standby clear, Explorer watchdog
    trigger, App Control, OneDrive stop). See FEATURE_AUDIT.md.
  - A screen-reader walk-through.
- **Known limitations:**
  - No authentication, so loopback only.
  - Metrics are polled (ADR-005).
  - `app.py` is large.
- **Rollback:**
  - Scripted install: `git switch --detach v4.1.0` in the checkout, then
    restart. State files are compatible.
  - Store: reinstall `SysPerf_4.1.0.0_x64.msix`.
- **Next highest-value step:** the clean-machine MSIX test, for example in
  Windows Sandbox or a fresh VM.
